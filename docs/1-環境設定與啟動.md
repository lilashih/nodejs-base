# 1. 環境設定與啟動

本篇說明專案之環境前置需求、快速啟動流程、環境變數（`.env`）管理架構、服務生命週期檢查機制，以及所有自訂 `pnpm` 指令完整說明。

---

## 一、快速入門（安裝與啟動）

### 1.1 環境前置需求

- **Node.js**：22.5.0 以上
- **pnpm**：10.0.0 以上
- **SQLite**：SQLite 模式使用 Node.js 內建的 `node:sqlite`，無須另外安裝 SQLite 程式或套件。
- **MySQL**：8.0.13 以上（MySQL 模式）
- **Bun**（選用）：1.1 以上（若需執行二進位執行檔打包）

### 1.2 套件安裝與環境檔建立

本專案後端與前端各自具備獨立的 `package.json`，於專案根目錄依序執行：

```bash
# 1. 安裝後端依賴套件
pnpm install

# 2. 安裝前端依賴套件
pnpm --dir frontend install

# 3. 複製環境設定範本
cp .env.example .env
```

### 1.3 資料庫初始化與遷移

1. 編輯 `.env`，選擇資料庫類型（`DB_CLIENT=sqlite` 或 `DB_CLIENT=mysql`），並設定自訂的 `JWT_SECRET`（長度至少 32 字元）。
2. 依所選資料庫完成設定：
   - **SQLite**：設定 `SQLITE_FILE`（例如 `storage/database/database.sqlite`），資料庫檔案及其上層目錄會在連線時自動建立，無須預先建立資料庫。
   - **MySQL**：填入 `MYSQL_HOST`、`MYSQL_USER`、`MYSQL_PASSWORD` 等連線資訊，並手動建立空資料庫：
     ```sql
     CREATE DATABASE nodejs_base CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
     ```
3. 執行資料庫遷移（Migration）建立資料表：
   ```bash
   pnpm migrate
   ```

### 1.4 啟動開發環境

```bash
pnpm dev
```

- `pnpm dev` 會先完整建置前端產物至 `frontend/dist/`，接著以 PM2 監控模式在背景啟動後端，並在前台持續監看前端檔案變更，透過該指令，前後端皆以熱加載模式啟動方便開發。
- 預設監聽位址為 `http://127.0.0.1:3000`
  - **前端頁面**：開啟 `http://127.0.0.1:3000/app/`
  - **API 連線測試**：存取 `http://127.0.0.1:3000/api/health`
  - **API 文件（Swagger UI）**：在 `debug` 或 `test` 模式下開啟 `http://127.0.0.1:3000/apidoc`
- **結束開發**：在終端機中按 `Ctrl + C` 結束前端監看，背景運行的 PM2 後端程序可透過以下指令停止：
  ```bash
  pnpm stop
  ```

## 二、環境變數架構與規範（`.env`）

### 2.1 核心原則

嚴格遵循 **「設定歸環境，指令歸腳本」** 的原則：
- **禁止**在 `package.json` 的 script 中硬編碼環境參數，例如以下寫法**不符合本專案規範**。
  ```json
  {
    "scripts": {
      "start:node": "APP_MODE=debug APP_PORT=3000 node src/app.js"
    }
  }
  ```
- 所有執行階段參數統一由專案根目錄的 `.env` 檔案管理。
- 業務模組**嚴禁直接存取 `process.env`**，一律透過 `src/config/` 統一出口讀取，由設定模組負責型別轉換、預設值注入與防呆驗證。

### 2.2 環境檔分類與職責

| 檔案 | 用途說明 | 版本控制狀態 |
| --- | --- | --- |
| `.env.example` | 環境變數範本檔，列出專案所需之設定鍵名與開發預設值。 | 納入版本控制（Git） |
| `.env` | 本地開發或伺服器正式環境之實際設定檔。 | **嚴禁**納入版本控制 |
| `.env.test` | 自動化測試專用設定檔（包含測試 DB、測試 Port、測試 Fixture 路徑）。 | 納入版本控制（Git） |
| `.env.test.local` | 開發者本地測試覆寫檔（選用，優先度高於 `.env.test`）。 | **嚴禁**納入版本控制 |

### 2.3 後端與程序管理載入機制

後端由 Node.js 執行期載入環境變數：
- **原生 Node 指令**：透過 Node 原生參數 `node --env-file=.env src/app.js` 載入 .env 路徑。
- **PM2 載入機制**：在 [ecosystem.config.js](../ecosystem.config.js) 中透過 `node_args: "--env-file=.env"` 同樣將 .env 路徑設定注入 Node 進程，維持單一檔案來源。

### 2.4 前端環境變數規範

- **同源共用**：前端與後端共用根目錄的同一份 `.env`。
- **Vite 讀取**：[frontend/vite.config.js](../frontend/vite.config.js) 已設定 `envDir: "../"`，建置時自動讀取根目錄環境變數。
- **安全性與限制**：
  - 僅具備 `VITE_*` 前綴之變數會暴露給前端（如 `VITE_APP_NAME`）。
  - 前端打包後為純靜態檔案，**正式環境運行時無法讀取伺服器上的 `.env`**，正式環境的值必須寫在 [frontend/src/config/config.js](../frontend/src/config/config.js) 的預設值中給定。
  - **嚴禁**在前端放入任何私鑰、密碼等機密資訊。

### 2.5 完整環境變數參考表

#### (1) 基礎應用設定
| 變數名稱 | 程式預設值 | 說明與範例 |
| --- | --- | --- |
| `APP_MODE` | `production` | 執行模式（`production`、`debug`、`test`），僅 `debug`/`test` 開放 Swagger UI。 |
| `APP_HOST` | `127.0.0.1` | HTTP 監聽 IP，若需對外直接存取請設為 `0.0.0.0`。 |
| `APP_PORT` | `3000` | HTTP 通訊埠，前端、API 與靜態檔案共用此 Port。 |
| `APP_TRUST_PROXY` | `loopback` | 反向代理信任設定（見 [第 11 篇](11-正式部署與反向代理.md)）。 |
| `APP_FRONTEND_PATH` | *(自動解析)* | 前端靜態資源實體路徑（預設依序偵測 `frontend/dist` 與 `dist`，測試環境可自訂如 `test/frontend/app`）。 |

#### (2) 資料庫設定
| 變數名稱 | 程式預設值 | 說明與範例 |
| --- | --- | --- |
| `DB_CLIENT` | `mysql` | 資料庫類型，可設為 `mysql` 或 `sqlite`。 |
| `SQLITE_FILE` | `storage/database/database.sqlite` | SQLite 檔案路徑，相對路徑以程式根目錄為基準，也可使用 `:memory:` （僅 SQLite 模式）。 |
| `MYSQL_HOST` | `127.0.0.1` | MySQL 主機位址。 |
| `MYSQL_PORT` | `3306` | MySQL 連線通訊埠。 |
| `MYSQL_USER` | `root` | 資料庫使用者名稱。 |
| `MYSQL_PASSWORD` | *(空字串)* | 資料庫使用者密碼。 |
| `MYSQL_DATABASE` | `nodejs_base` | 資料庫名稱（需手動預先建立）。 |
| `MYSQL_CONNECTION_LIMIT` | `10` | 連線池最大連線數量。 |

#### (3) 日誌系統設定
| 變數名稱 | 程式預設值 | 說明與範例 |
| --- | --- | --- |
| `LOG_LEVEL` | `info` | 記錄層級（`error`、`warn`、`info`、`http`、`verbose`、`debug`、`silly`）。 |
| `LOG_ENABLE_ACCESS_LOG` | `true` | 是否啟用獨立的 HTTP Access 日誌（`true` / `false`）。 |
| `LOG_RETENTION_DAYS` | `0` | 日誌輪替保留天數，`0` 表示永久保留。 |

#### (4) 認證與安全性設定 (JWT / Cookie)
| 變數名稱 | 程式預設值 | 說明與範例 |
| --- | --- | --- |
| `JWT_SECRET` | *(無預設)* | JWT 簽發金鑰，**長度必須至少 32 個字元**，啟動時強制驗證。 |
| `JWT_EXPIRES_IN` | `1h` | Token 有效期限（如 `1h`、`7d`）。 |
| `JWT_ISSUER` | `nodejs-base` | JWT 簽發者識別名稱。 |
| `JWT_AUDIENCE` | `nodejs-base-api` | JWT 受眾識別名稱。 |
| `COOKIE_SECURE`| `false` | Cookie Secure 旗標，正式 HTTPS 環境請設為 `true`。 |
| `CORS_ORIGINS` | `http://localhost:3000` | 允許之 CORS 來源清單，多個來源以逗號分隔。 |

#### (5) 檔案上傳與請求限制
| 變數名稱 | 程式預設值 | 說明與範例 |
| --- | --- | --- |
| `UPLOAD_MAX_FILE_SIZE` | `2097152` | 單張圖片解碼上限，單位為 bytes（預設約 2 M）。 |
| `UPLOAD_JSON_LIMIT` | `10mb` | JSON 與 URL-encoded Request Body 之傳輸上限。 |

## 三、服務啟動與生命週期機制

### 3.1 啟動條件依序檢查

[src/app.js](../src/app.js) 啟動時會嚴格依序驗證以下三項條件，任一條件不符將立即中斷啟動並記錄錯誤：
1. **JWT 密鑰長度驗證**：檢查 `authConfig.jwt.secret` 長度是否達到 32 字元。
2. **前端資源可用性檢查**：僅在正式環境（`production`）模式下會檢查前端，確認實體靜態檔案（`index.html`）或執行檔內嵌至少一者存在。
3. **資料庫連線測試**：對所選資料庫執行 `SELECT 1 AS connected` 測試，確保連線正常。

### 3.2 執行架構與模式比較

| 執行模式 | 指令範例 | 適用場景 | 特色說明 |
| --- | --- | --- | --- |
| **整合開發** | `pnpm dev` | 本機日常開發 | 熱加載模式，前端即時監看重編 + PM2 後端程式碼變更自動重啟。 |
| **前景除錯** | `pnpm start:node` | 啟動排錯、觀察 stdout | 原生 Node 前景直出，無程序管理，Ctrl+C 即停止。 |
| **背景常駐** | `pnpm start` | 傳統伺服器部署 | 由 PM2 管理，包含記憶體超限保護與異常崩潰重啟。 |
| **Bun 單檔** | `./app.exe` (或 `./app`) | 輕量或無 Node 主機部署 | 獨立二進位單檔，免 Node.js/PM2 環境，極速啟動（詳見 [第 10 篇](10-Bun打包說明.md)）。 |

### 3.3 平緩關閉（Graceful Shutdown）

服務監聽作業系統訊號與全域例外：
- 收到 `SIGINT` 或 `SIGTERM` 時，依序關閉 HTTP 監聽器與資料庫連線，確保已進行中的請求處理完畢後才安全結束進程。
- 攔截未捕捉例外（`uncaughtException`）與未處理拒絕（`unhandledRejection`），記錄完整錯誤堆疊後安全退出進程。

## 四、專案指令完整參考（`pnpm Scripts`）

以下指令均於專案根目錄執行：

### 4.1 服務開發與啟動

| 指令 | 底層執行動作 | 使用情境與說明 |
| --- | --- | --- |
| `pnpm dev` | 前端 build ➔ PM2 啟動後端 watch ➔ 前台監看前端 | 推薦開發指令，前後端共用同一通訊埠，熱加載體驗。 |
| `pnpm start` | `pm2 delete` ➔ `pm2 start ecosystem.config.js` | 正式環境以 PM2 常駐啟動後端。 |
| `pnpm start:node` | `node --env-file=.env src/app.js` | 原生 Node 前景啟動，適合除錯啟動階段日誌。 |
| `pnpm stop` | `pm2 stop ecosystem.config.js` | 停止 PM2 背景運行的專案程序。 |

### 4.2 前端建置與監看

| 指令 | 底層執行動作 | 使用情境與說明 |
| --- | --- | --- |
| `pnpm build:frontend` | `pnpm --dir frontend build` | 執行 Vite 正式建置，輸出產物至 `frontend/dist/`。 |
| `pnpm dev:frontend` | `pnpm --dir frontend dev` | 僅啟動 Vite 監看前端檔案並自動重編，不啟動後端。 |
| `pnpm --dir frontend check` | `vue-tsc --noEmit` | 執行 Vue / TypeScript 型別檢查，不產出檔案。 |

> [!NOTE]
> 關於前端 Vue 3 架構、同源單埠整合、熱加載開發流程、SPA 路由 Fallback 託管與共用 HTTP 請求工具，請參閱 [第 9 篇：前端開發](9-前端開發.md)。

### 4.3 程式檢查與測試

| 指令 | 底層執行動作 | 使用情境與說明 |
| --- | --- | --- |
| `pnpm check` | `node scripts/checkSyntax.js` | 檢查全專案 JS 語法與 camelCase 命名規範。 |
| `pnpm test:unit` | 載入 `.env.test` 執行 `jest test/unit/` | 執行所有單元測試（包含 Service、Helper、規格等）。 |
| `pnpm test` | 載入測試環境執行全套測試 | 執行整合與單元測試。 |
| `pnpm test:coverage` | 載入測試環境並附帶 `--coverage` | 產生 Jest 測試覆蓋率報告。 |

> [!NOTE]
> 關於自動化測試架構、環境隔離（`.env.test` 與 `.env.test.local`）、Mock 隔絕策略、測試覆蓋率分析與單檔測試指南，請參閱 [第 8 篇：測試說明](8-測試說明.md)。

### 4.4 資料庫遷移（Migration）

專案透過自訂的 [scripts/migrate.js](../scripts/migrate.js) 封裝 Knex 遷移引擎，提供資料庫升級、回滾、重置與鎖管理功能：

| 指令 | 底層執行動作 | 簡要說明 |
| --- | --- | --- |
| `pnpm migrate` | 執行 `scripts/migrate.js up` | 向上套用所有尚未執行的遷移。 |
| `pnpm migrate:rollback` | 執行 `scripts/migrate.js rollback` | 回滾最後一批遷移（支援 `--step=N` 逐筆回滾與 `--yes` 略過確認）。 |
| `pnpm migrate:unlock` | 執行 `scripts/migrate.js unlock` | 強制釋放遷移鎖（用於程序中斷後卡死時解鎖）。 |
| `pnpm migrate:fresh` | 執行 `scripts/migrate.js fresh` | **刪除資料庫並重建、重新執行全部遷移**（僅限 `debug`/`test` 模式）。 |
| `pnpm migrate:create <name>` | 執行 `scripts/createMigration.js` | 建立新遷移檔案骨架（`<name>` 須為 camelCase，建立後須登錄至 registry）。 |

> [!NOTE]
> 關於 Migration 完整 CLI 參數細節（如 `--step=N`、`--yes`）、`fresh` 雙重安全防護機制、遷移鎖、排查 SOP，以及靜態登錄與 Schema 撰寫規範，請參閱 [第 4 篇：資料庫與 Migration](4-資料庫與Migration.md#六完整-cli-指令集與防呆安全機制)。
